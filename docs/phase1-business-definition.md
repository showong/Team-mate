# Team-mate PHASE 1 — 업무 정의

## 1. 요약

Team-mate PHASE 1은 여러 LLM을 하나의 가상 부서처럼 구성해, 사용자가 입력한
아젠다에 대해 **조사 → 검토 → 품질검수 → 재작업 → 최종 보고**를 수행하는
AI 리서치 업무 자동화 프로젝트다. 외부 워크플로우 자동화 툴(n8n 등)을
사용하지 않고, GitHub 레포지토리로 관리 가능한 코드 기반 오케스트레이션
시스템으로 설계한다.

## 2. PHASE 1 핵심 목표

| 구분 | 내용 |
| --- | --- |
| 프로젝트 형태 | GitHub 레포지토리 기반 개발 프로젝트 |
| 외부 워크플로우 툴 | 사용하지 않음 |
| 핵심 기능 | 조사, 검토, 품질검수, 재작업, 최종 보고 |
| 주요 구조 | 코드 기반 Workflow Orchestrator |
| 검증 목표 | 멀티 LLM 협업 구조가 실제로 유효한지 확인 |
| 비용 전략 | 저비용 모델은 조사, 고성능 모델은 검수 중심 |
| 확장 방향 | 향후 아이디어 미팅, 전략회의, 멀티부서 구조로 확장 |

## 3. 업무 범위

### 3.1 포함

- 아젠다 입력
- 업무 난이도 판단
- 업무 분해
- 주임 조사
- 대리 검토 / 통합
- 부팀장 검수
- 부분 재작업
- 최종 보고서 생성
- 중간 과정 / 비용 / 성과 기록

### 3.2 제외 (PHASE 1 범위 외)

- 아이디어 미팅 / 자유토론
- 전략회의
- 다중 팀 동시 운영
- 자동 승진 / 강등
- PPT 자동 생성
- 실시간 회의형 UI

## 4. 조직 구조

```
팀장: 사용자
│
├─ 주임 A: 저비용 모델 / 시장·배경 조사
├─ 주임 B: 저비용 모델 / 직무·역량 조사
├─ 주임 C: 저비용 모델 / 사례·적용 가능성 조사
│
├─ 대리   : 중상급 모델 / 검토 · 통합 · 초안 작성
└─ 부팀장 : 고성능 모델 / 품질검수 · 승인 판단
```

### 산출물 형식

#### 주임

1. 담당 조사 범위
2. 핵심 요약
3. 주요 발견사항
4. 근거 및 출처
5. 불확실한 내용
6. 대리에게 전달할 체크포인트

#### 대리

1. 통합 보고서 초안
2. 주임별 반영 내용
3. 제외한 내용과 사유
4. 추가 확인이 필요한 주장
5. 부팀장 검수 요청사항

#### 부팀장 검수 항목

| 항목 | 설명 |
| --- | --- |
| 사실성 | 근거 없는 단정 여부 |
| 출처 품질 | 출처가 충분하고 적절한지 |
| 논리성 | 주장과 근거가 연결되는지 |
| 목적 적합성 | 사용자 목적에 맞는지 |
| 중복성 | 단순 취합 수준은 아닌지 |
| 할루시네이션 위험 | 허위 정보 가능성 |
| 완성도 | 최종 보고서로 제출 가능한지 |

## 5. 성공 기준

### 기능

| 기준 | 성공 조건 |
| --- | --- |
| 업무 완주 | 아젠다 입력 → 최종 보고서까지 완료 |
| 역할 구분 | 주임/대리/부팀장 결과물이 명확히 다름 |
| 상태 관리 | 각 단계 상태가 정상 저장 |
| 검수 작동 | 부팀장 승인 / 조건부 / 반려 판단 수행 |
| 재작업 작동 | 반려 시 특정 파트만 재작업 |
| 무한 루프 방지 | Max Retry 초과 시 Circuit Breaker 작동 |
| 비용 기록 | 토큰과 예상 비용이 저장 |
| 로그 조회 | 중간 과정 확인 가능 |

### 품질

| 기준 | 성공 조건 |
| --- | --- |
| 출처 관리 | 핵심 주장에 근거가 연결 |
| 중복 제거 | 단순 합친 수준이 아님 |
| 불확실성 표시 | 확인되지 않은 내용 별도 표시 |
| 목적 반영 | 사용자 목적에 맞는 결론 |
| 보고서 완성도 | 사람이 읽을 수 있는 구조화된 보고서 |
| 비용 대비 품질 | 단일 고성능 모델 호출 대비 효율성 확인 가능 |
